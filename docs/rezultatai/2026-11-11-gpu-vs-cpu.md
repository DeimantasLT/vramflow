# GPU prieš CPU — talpos palyginimas

PASS griežtai = 0 praradimų ir 0 teisingumo klaidų; PASS tol = 0 teisingumo klaidų ir praradimai ≤ 0,2 % (atskiria pavienius platformos sutrikimus nuo talpos ribos). CPU — funkcijos proceso branduoliai srautui (be šaltinio ir patikros). Šaltinis „fair“ — C variantui naudojamas pigus GPU→host generatorius, kad būtų matuojama funkcija, o ne sintetinis CPU generatorius.

## Pastabos (būtina skaityti kartu su lentele)

- **Aplinka:** RTX 4070 Laptop 8 GB (1 NVENC, 1 NVDEC variklis), WSL2 Ubuntu 24.04 ant Windows 11. Dec ir grandinės
  kampanijos vyko su Windows energijos profiliu „Whisper“ (tylusis, ribota galia); logo kampanija — prieš perkrovimą,
  kitu profiliu. Skaičiai orientaciniai; autoritetingi — natyviame Linux su užfiksuotais GPU dažniais.
- **Grandinės G N\* = 1 yra artefaktas, ne talpa.** Ties N=2 GPU apkrova per maža, ir nešiojamo kompiuterio GPU kas
  ~6 s numeta SM dažnį 1605 → 210 MHz (išmatuota 1 Hz zondu, `vramflow-check2/chain-G-n2/gpu.csv`). Kol dažnis vėl
  pakyla, praleidžiami realaus laiko terminai visuose trijuose procesuose vienu metu (abiejų flow'ų skaitikliai
  identiški). Pakartota 3 kartus: 18–23 % praradimų. Ties N=4…12 dažnis stabilus ir visos pakopos PASS_tol, todėl
  „Nauda G/C“ grandinei šioje eilutėje neinterpretuotina; realus santykis — **≥ 12 prieš 4 (≥ 3×)**.
  Išvada diegimui: realaus laiko GPU media funkcijoms reikia užfiksuotų dažnių (`nvidia-smi -pm 1`, `-lgc`/aplikacijos
  dažniai serveryje; Windows — „Prefer maximum performance“).
- **GPU apkrova grandinėje (G):** N=4 — SM 4 %, NVENC 42 %, NVDEC 32 %, 13 W; N=12 — SM 10 %, NVENC 64 %, NVDEC 50 %,
  34 W (2595 MHz). Ribojantis išteklius — vienintelis NVENC variklis, ne CUDA skaičiavimas; serverių GPU su 2–3 NVENC
  varikliais riba atitinkamai aukštesnė (neišmatuota).
- **Grandinės C** riba — CPU: ~2 branduoliai flow'ui (x264 superfast + programinis H.264 dekoderis + logo).
