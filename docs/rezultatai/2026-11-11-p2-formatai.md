## Chromos PSNR prieš FFmpeg (`tests/perf/chroma_psnr.py`, ctest `chroma_psnr_*`)

Mūsų 4:2:2 10 bitų prieš `ffmpeg -vf scale=flags=bilinear -pix_fmt yuv422p10le` (pikas 1023), 3 kadrai. Peržiūra
pastebėjo, kad pirminis etalonas (swscale numatytasis bicubic) matavo kitą interpoliatorių, ne teisingumą: prieš bilinear
mūsų kadro chroma — bitas į bitą.

| Šaltinis | Kadro chroma prieš bilinear Y / U / V | Lauko chroma (senas kelias) U / V, dB | Informacijai: kadro chroma prieš bicubic U / V, dB |
|---|---|---|---|
| zonų plokštė `kx2=ky2=20`, 1080p50 | inf / inf / inf | 49,1 / 49,0 | 57,7 / 57,7 |
| generatoriaus klipas, 1080p50 | inf / inf / inf | 48,7 / 48,1 | 60,9 / 60,3 |
| zonų plokštė, 720p50 | inf / inf / inf | 48,3 / 48,5 | 57,5 / 57,6 |
| generatoriaus klipas, 720p50 | inf / inf / inf | 48,8 / 47,9 | 61,0 / 60,1 |

Kriterijus (ctest `chroma_psnr_{1080p50,1080p25,720p50}`): kadro chroma bitas į bitą, lauko chroma < 50 dB.

## Chroma po kodavimo: gen | enc | dec | verify (`verify --min-chroma-db`)

Cb/Cr PSNR prieš gen etaloną (šaltinio indeksas iš barkodo), 1080i50, NVENC 18 Mbit/s: `dec --chroma-siting field`
min 44,9 / vid. 45,5 dB; `auto` (NVENC kadrai pažymėti progresyviais → kadro chroma, laukai maišomi) min 36,8 / vid.
36,9 dB. NVENC šioje GPU lauko kodavimo neturi (`-flags +ildct` — encoder open klaida, `field_order` = progressive),
todėl mūsų NVENC 1080i srautams dec reikia `--chroma-siting field`. Riba: NVENC 41 dB, x264 ultrafast 37 dB
(x264 min 38,9–41,1 dB).

Išvados:
- 1080i50 nepablogėjo daugiau nei 3 % (G +1,6 %, C +2,1 % — vienas histogramos žingsnis).
- Progresyvus grain'as — 2× daugiau duomenų: C variantas N = 8 su 1080p50 viršija CPU talpą (gen + logo tame pačiame
  CPU), 1080p25 — ties riba. G variantas visais formatais be praradimų.
- 1080p25 G p50 10,9 ms — ne kodo savybė, o GPU galios būsena (P8 tarp 40 ms tick'ų). Peržiūros matavimas: 1080p25
  10,88 ms vienas prieš 2,59 ms su papildoma GPU apkrova; 1080p50 5,05 prieš 2,20 ms. Lentelės G skaičiai matuoti be
  papildomos apkrovos (GPU gali užmigti tarp tick'ų), todėl formatų G laikus palyginti tarpusavyje negalima; su GPU
  palaikoma apkrauta (fiksuoti taktai arba fonu veikiantis darbas) šis matavimas nepakartotas — apribojimas.
- SM % nematuota (nebuvo nsys / nvidia-smi zondo šiame bėgime).

## Peržiūros pataisos

- chromos PSNR etalonas — bilinear, kriterijus bitas į bitą;
- `dec --chroma-siting auto|field|frame`, NVENC 1080i srautams `field`;
- `composite` laukė 1080i50 laikrodžiu (`wait_until(i, …)`): 25p tick'as pabusdavo prieš grain'o laiką (`early_wakes`
  500 per 10 s, wait_ms p50 39 ms) — pataisyta;
- logotipo numatytoji vieta nuo rastro; sync blyksnis kartą per sekundę bet kuriuo dažniu, x ir gradientai pagal rastrą;
  dalyba pikseliui pakeista tikslia daugyba (gen C 1080i50 N = 2: 8,3 → 6,5 ms p50);
- `libvramflow-gfx` priima visus palaikomus dažnius (autoriaus sprendimas; R9 testas pakeistas).
- generatoriaus kernel'is: parametrai (dalikliai, blyksnis) ruošiami host'e — 64 bitų dalybos kiekvienoje gijoje kartu su
  gfxgen sukeldavo ~200 ms GPU stabdymus (gen commit max 201 ms, 27 praleidimai per 20 s 1080p50); po pataisos max 4,3 ms.
