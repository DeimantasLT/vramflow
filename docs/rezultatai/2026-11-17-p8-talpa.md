# P8 talpos kampanija: kelias su pakartojimais (2026-11-17)

**Aplinka:** RTX 4070 Laptop 8 GB, tvarkyklė 596.49, CUDA 13.2, WSL2 Ubuntu 24.04, `cuda_arch_build=native`, kodas
`b5f670e` (funkcijos — `8d8a62b`). Variantas G (GPU apdorojimas, `cuda-linear` flow'ai), 1080i50, `keepwarm` įjungtas.
Laikrodžio zondas prieš / po: −1,1 / −0,3 ppm, 0 žingsnių.

**Metodas:** `capacity.py --n auto --repeats 3 --seconds 30 --warmup 10` (`tests/perf/knee.py`): N dvigubinamas iki
pirmo FAIL arba `--n-max`, tada dalijama pusiau; pakopa PASS tik jei praeina **visi 3** pakartojimai (tol kriterijus:
0 teisingumo klaidų, ≤ 0,2 % praradimų, RT ≥ 0,999, visi procesai exit 0). VRAM srautui — `ΔVRAM(N)` tiesės nuolydis
per PASS pakopas (mažiausi kvadratai). Pakopos 30 s, ne 60 s kaip README §8 „prieš“ — trumpesnis langas retesnius
sutrikimus gali praleisti; tai kompensuoja 3 pakartojimai.

## Radiniai

1. **NVENC riba = sesijų skaičius, ne pralaidumas.** N ≥ 13: `OpenEncodeSessionEx failed: incompatible client key
   (21)` (`enc.err`), visi koduotuvai neatsidaro, RT = 0. Ties N = 12 NVENC apkrautas 64 % — pralaidumo rezervas yra, bet
   GeForce tvarkyklė leidžia 12 vienalaikių sesijų. `capacity.py` tai dabar žymi `driver_limit = nvenc_sessions`, o kelio
   santrauka — `stopped_by = nvenc_sessions` (patikrinta pakartotiniu paleidimu). Profesionalios (RTX A / L serijos)
   GPU šios ribos neturi — ten kelias bus kitas; nepatikrinta.
2. **13-a sesija nuverčia visą `enc` procesą** (exit 2), ne tik naują srautą. Priėmimo kontrolei (P4): NVENC sesijų
   skaičius turi būti atskiras ribotas resursas šalia Mpix/s ir VRAM.
3. **Grandinės kelias 11, ne NVENC.** README §8 teiginys „vienintelis NVENC variklis — riba“ neteisingas: ties N = 12
   NVENC 63 %, NVDEC 51 %, o FAIL priežastis — vėlavimai (`dec.late_skips` 24, `logo.late_fields` 24, `enc.late_frames`
   12; 0,52 % praradimų). Kuri grandies dalis vėluoja pirmoji — neištirta. N = 16 — vėl sesijų riba.
4. **Kompozitorius K = 2: kelias ≥ 32** (prieš: N\* 2 tolerantiškai / 0 griežtai, README §8). Skirtumas — GPU laikrodis:
   tuomet 210–690 MHz be `keepwarm`, dabar 550–1112 MHz su `keepwarm`. Tai patvirtina README hipotezę, kad ankstesni G
   kritimai buvo laikrodžio, ne kodo; ΔVRAM ties 32 = 4,3 GB.
5. **NVDEC kelias 22** (prieš: 24 tolerantiškai / 16 griežtai, viena matavimo serija). Dabar su 3 pakartojimais 22 —
   stabilus; 23 ir 24 krenta ties 0,29–0,35 % praradimų, NVDEC 96–100 %.
6. **VRAM modelis tiesinis** (R² ≥ 0,997 visur): 8 GB GPU teoriškai talpintų ~130 logo arba ~60 kompozitoriaus K = 2
   srautų — riba bus SM / laikrodis, ne atmintis; nepatikrinta virš 64 / 32.

## Ko nepatikrinta

- C ir H variantai šia metodika (tik G); `--n-max` virš 64 (logo) ir 32 (kompozitorius).
- Natyvus Linux (ne WSL2), serverinė GPU, užrakinti laikrodžiai.
- Grandinės vėlavimų ties N = 12 priežastis.
